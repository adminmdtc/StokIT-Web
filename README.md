# IT Stock — ระบบบริหารจัดการวัสดุและอุปกรณ์ กลุ่มงานไอที

เว็บแอปจัดการคลังวัสดุ/อุปกรณ์ของกลุ่มงานเทคโนโลยีสารสนเทศ ใช้งานได้ทันทีโดยไม่ต้องติดตั้งอะไรเพิ่ม — เปิดไฟล์ `index.html` บนเบราว์เซอร์ก็ใช้งานได้ (ข้อมูลเก็บใน localStorage ของเบราว์เซอร์)

## ฟีเจอร์

| เมนู | ความสามารถ |
|---|---|
| **หน้าหลัก** | สถิติภาพรวม มูลค่าคงเหลือ แผนภูมิการเคลื่อนไหว 6 เดือน วัสดุใกล้หมด รายการล่าสุด — **banner แจ้งเตือนสีส้ม-แดง** ด้านบนเมื่อมีวัสดุใกล้หมด/หมดคลัง พร้อมปุ่มไปหน้าคงเหลือ |
| **รับเข้าวัสดุ** | บันทึกวัสดุรับเข้า ระบุผู้จัดจำหน่าย ราคา/หน่วย (อัปเดตราคาต้นทุนอัตโนมัติ) เพิ่มได้หลายรายการในเอกสารเดียว พิมพ์**ใบรับเข้าวัสดุ**ได้ |
| **จำหน่าย / เบิกจ่าย** | บันทึกการเบิกจ่าย ระบุผู้รับ/หน่วยงาน **ระบบตรวจสอบจำนวนคงเหลืออัตโนมัติ** ป้องกันการเบิกเกิน พิมพ์**ใบเบิกวัสดุ**ได้ |
| **คงเหลือ** | ยอดคงเหลือปัจจุบัน ค้นหา/กรองตามหมวดหมู่ สถานะ เพียงพอ / ใกล้หมด / หมดคลัง เพิ่ม-แก้ไข-ลบวัสดุ |
| **รายงาน** | รายงานคงเหลือ / รับเข้า / จำหน่าย กำหนดช่วงวันที่ได้ ส่งออกเป็น **Excel (.xlsx)** และ **PDF (พิมพ์)** |
| **เอกสารรายการ** | คลิกปุ่มพิมพ์ที่แถวประวัติรับเข้า/จำหน่าย → เปิด**ใบรับเข้าวัสดุ / ใบเบิกวัสดุ** พร้อมเลขที่เอกสาร จำนวนเงินเป็นตัวอักษร และช่องลายเซ็น (ผู้ส่งมอบ/ผู้รับ/ผู้ตรวจรับ หรือ ผู้เบิก/ผู้จ่าย/ผู้อนุมัติ) พิมพ์/บันทึกเป็น PDF ได้ |
| **ป้ายวัสดุ QR** | ปุ่มป้ายที่หน้าคงเหลือ (หรือ "พิมพ์ป้ายทั้งหมด") → สร้าง**ป้ายวัสดุพร้อม QR Code** (เข้ารหัสรหัสวัสดุ เช่น IT-0001) ขนาด 90×50 มม. วาง 2 คอลัมน์ต่อ A4 กำหนดจำนวนป้ายได้ สแกนเพื่อค้นหาวัสดุ |
| **แจ้งเตือนวัสดุใกล้หมด** | ป้ายแดงนับจำนวนวัสดุใกล้หมด/หมดคลังที่เมนูคงเหลือ (อัปเดตอัตโนมัติทุกครั้งที่ข้อมูลเปลี่ยน) + **toast แจ้งเตือนทันทีเมื่อล็อกอิน** หากมีวัสดุต่ำกว่าจำนวนขั้นต่ำ |
| **สแกนค้นหาวัสดุ** | หน้าคงเหลือรองรับ 2 วิธี: **(1)** เครื่องสแกนบาร์โค้ด — พิมพ์รหัสในช่องค้นหาแล้วกด Enter **ไม่ต้องกดปุ่มใดๆ** และ **(2)** ปุ่ม "สแกน QR" เปิดกล้องสแกนป้ายวัสดุ — เมื่อเจอจะไฮไลต์แถววัสดุและเลื่อนมาให้อัตโนมัติ |
| **Serial / Inventory Tag** | วัสดุราคาสูง (โน้ตบุ๊ก เครื่องพิมพ์ สวิตช์ ฯลฯ) เปิด "ติดตามเป็นรายชิ้น" ได้ในฟอร์มวัสดุ — **รับเข้า**ต้องระบุ Serial ทุกชิ้น (วางหลายบรรทัดได้) **จำหน่าย**เลือก Serial เฉพาะชิ้นที่เบิกออก ระบบตรวจสอบความถูกต้องอัตโนมัติ (Serial ซ้ำ/ไม่มีในคลัง/ยังอยู่ในคลัง) และปุ่ม `#` ที่หน้าคงเหลือเปิดประวัติรายชิ้น: สถานะ เอกสารรับเข้า ผู้รับ และวันที่เบิก |
| **ผู้ใช้งาน** | จัดการบัญชีผู้ใช้และสิทธิ์ (เฉพาะผู้ดูแลระบบ) |

> วัสดุตัวอย่างที่ติดตามเป็นรายชิ้นในข้อมูลเริ่มต้น: โน้ตบุ๊ก Lenovo (IT-0001), โน้ตบุ๊ก Dell (IT-0002), จอ LED (IT-0005), เครื่องพิมพ์ (IT-0006) และ Switch (IT-0010) — Serial อยู่ในรูปแบบ `NB-2026-XXX`, `MN-2026-XXX`, `PR-2026-XXX`, `SW-2026-XXX`

|---|---|---|
| ผู้ดูแลระบบ (จัดการทุกอย่าง) | `admin` | `admin123` |

เปลี่ยนรหัสผ่านได้โดยคลิกที่บัตรผู้ใช้ (มุมซ้ายล่างของเมนู)

## วิธีรัน

ตัวเลือกที่ 1 — เปิดตรง ๆ:
เปิดไฟล์ `index.html` ในเบราว์เซอร์ (Chrome/Edge) เลย

ตัวเลือกที่ 2 — รันผ่านเซิร์ฟเวอร์ท้องถิ่น (แนะนำ):
```bash
python -m http.server 8137 --bind 127.0.0.1
# แล้วเปิด http://127.0.0.1:8137
```

## โครงสร้างไฟล์

```
index.html        หน้าเว็บหลัก (โครงสร้าง + หน้าเข้าสู่ระบบ)
css/styles.css    สไตล์ทั้งหมด (ธีมทันสมัย + สไตล์การพิมพ์รายงาน)
js/store.js       ชั้นข้อมูล: localStorage, ข้อมูลตัวอย่าง, คำนวณคงเหลือ, ระบบล็อกอิน
js/ui.js          ตัวช่วย UI: ไอคอน, ฟอร์แมตตัวเลข/วันที่, ทอสต์, โมดัล
js/export.js      ส่งออก Excel (SheetJS + fallback CSV) และ PDF (พิมพ์)
js/views.js       เรนเดอร์ทุกหน้า + ตัวจัดการเหตุการณ์
js/app.js         จุดเริ่มต้น, เราเตอร์, การผูกเหตุการณ์
```

## หมายเหตุ

- ข้อมูลทั้งหมดเก็บใน **localStorage** ของเบราว์เซอร์ — การเคลียร์ข้อมูลเบราว์เซอร์จะทำให้ข้อมูลหาย (ปุ่ม "รีเซ็ตข้อมูลตัวอย่าง" ที่เมนูด้านข้างสำหรับคืนค่าเริ่มต้น)
- การส่งออก PDF ใช้หน้าต่างพิมพ์ของเบราว์เซอร์ — เลือก "บันทึกเป็น PDF" ได้ในหน้าต่างพิมพ์ (รองรับภาษาไทยอย่างสมบูรณ์)
- การส่งออก Excel ใช้ไลบรารี SheetJS จาก CDN หากออฟไลน์จะสำรองเป็นไฟล์ CSV (เปิดใน Excel ได้)
- ป้าย QR ใช้ไลบรารี qrcode-generator และการสแกนกล้องใช้ html5-qrcode จาก CDN หากออฟไลน์ ป้ายจะพิมพ์โดยไม่มีรหัส QR และการสแกนกล้องจะไม่ทำงาน (ใช้เครื่องสแกนบาร์โค้ดแทนได้)
- การสแกนด้วยกล้องต้องใช้งานผ่าน localhost/HTTPS และอนุญาตสิทธิ์กล้องในเบราว์เซอร์
- หากต้องการใช้จริงในองค์กร แนะนำให้ย้ายข้อมูลไปยังฐานข้อมูล/backend (เช่น SQLite/PostgreSQL + API) เพราะ localStorage เก็บได้จำกัดและไม่รองรับผู้ใช้หลายเครื่องพร้อมกัน
